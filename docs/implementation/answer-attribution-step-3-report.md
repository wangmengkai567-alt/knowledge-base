## 1. 最终模型输出契约

模型最终输出改为 `answer_contract_version=2`，仅接受 `status/claims/missing`。旧的自由 `answer` 字段已删除，不保留兼容解析或自动修复。

每条事实包含：

| 字段 | 作用 |
|---|---|
| `scope` | `source` 表示单个原始来源的表述，`shared` 表示多来源共同结论 |
| `text` | 单行事实段落，不能手写引用、插入多段尾文或代码围栏 |
| `evidence` | 每份依据由已选引用编号 `citation_id` 和连续原样摘录 `quote` 组成 |
| `code` | 完整命令或代码；没有代码时为 null |

`answered` 必须有事实且缺失项为空；`insufficient` 必须给出尚缺依据的主题，可以保留已获支撑的事实。`missing` 仅允许单行短主题，由程序统一呈现为“本次已读取的资料尚未覆盖……的充分依据”，不提供自由总结段落。

详细输出规则只在最终阶段加入，原生探索阶段不重复携带长协议说明；模型仍通过原有工具选择证据。结构化 Schema、最终规则和实际消息一起计入顺序 2 的预算规划，没有增加模型调用或扩大输出上限。

## 2. 发布前检查与渲染

新的[回答渲染模块](../../ai-service/internal/biz/answer_rendering.py)负责以下确定性检查：

1. 每份引用必须属于本次实际送模资料；已执行 `finish_research` 时还必须属于所选引用。
2. 摘录必须逐字出现在该引用对应的送模内容中。不能从未发送的完整快照、另一个窗口或其他条目的引用中借用文字；不通过空白修剪修复摘录。
3. `source` 的依据只可归于一个原始来源；`shared` 至少需要两个来源身份。知识库按知识库/文档身份去重，网页按规范网址去重，同文档多个块、同页多个窗口不重复计数。不同网址也不等于已经完成了内容独立性或转载关系调查。
4. `answered` 的每条事实均不得用搜索摘要替代正文。存在另一条正文事实，也不能替摘要事实补足凭据。
5. 完整代码和行内代码须在本条事实自己的非摘要摘录中原样出现，不能借其他事实的证据。程序生成代码围栏及其引用。
6. 手写引用、多段事实、游离字段、伪造摘录、引用越界等导致整份答案不发布，不自动重答，也不发布前半份已验证事实。

程序将规范事实渲染成面向用户的 Markdown，每段事实及代码均带对应引用。HTML 被作为文本处理，不能在一个条目中用标签另起无引用段落。外部 API/SSE 仍返回渲染后的 `answer`，不把内部模型 JSON 直接展示给用户。

实现同步更新了[最终载荷类型](../../ai-service/internal/biz/tool_types.py)、[发布入口](../../ai-service/internal/biz/rag.py)、[最终阶段提示](../../ai-service/internal/biz/tool_model.py)、[RAG 模板](../../ai-service/internal/prompt/templates/rag.yaml)及[界面错误说明](../../web/src/components/Search/SummaryPanel.vue)。

## 5. 明确的语义边界

另用一个刻意错误的结论验证边界：让模型声称“两份资料都明确说明镜像是容器的基础”，同时提供真实的知识库镜像/容器摘录与官方“容器是隔离进程”的摘录。两份摘录都真实、来源身份也不同，所以结构校验会接受；但官方摘录没有支持镜像基础角色，语义结论仍不成立。

诊断把它单列为未获语义认证的反例，没有将其计为正确回答。由此，本项可以拦截原 W03 的游离尾段、缺失引用、伪造摘录和错误来源数量，不能保证拦截所有用真实摘录包装的错误推理。单个来源条目的事实表述也仍需要语义判断。当前明确没有添加自动语义审查模型、无限额调用或关键词蕴含规则。
