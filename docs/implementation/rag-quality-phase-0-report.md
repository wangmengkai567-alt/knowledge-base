| 实际输入、输出 | 每个 `model_finished` 的 `prompt_tokens`、`completion_tokens` 分别累计；相同历史再次发送仍按该次报告累计 |

## 6. W02 原因核实

现有优化报告已经包含更正，本阶段核实后原样保留。W02 的 `keywords` 是合法字符串数组，两项长度分别为 31、37；第二项 `search_depth include_answer parameter` 超过本地每项 32 字符限制。总长度仍在 120 字符以内；不是数组类型错误，也不是 Tavily 供应商长度限制。

当前工具参数 Schema 的数组元素仅声明 `type: string`，未声明 `maxLength: 32`。用保存参数在现有容器中调用参数模型校验，重现 `keywords / value_error`，没有执行外部工具。原工具结果中的 `INVALID_TOOL_ARGUMENTS` 及泛化错误说明完整保留，没有重写历史错误。

更正的是原因说明：本地长度约束与模型可见 Schema 不一致，Tavily 请求尚未发出。统一 Schema、改进报错或调整长度边界均属于第 2 阶段，尚未实施。

## 7. 后续比较契约

每轮先核对冻结题集与评分表达表：黄金题集版本 `0.4`，90 道可答题有 130 个原要点、536 条等价表达。题干、参考答案、必答词、等价表达、陷阱规则、历史知识库范围、文档正文与版本必须一致；同时核对请求、模型、服务主机和执行上限。保留原始自动判分及失败分母，不能为了通过而临时改分。文档或规则发生变化时先明确记录版本差异，不将其当作同条件质量改善。

三类变化分别记录，不能合并成一个涨分数字：

| 比较类别 | 比较依据 | 必须排除的混淆 |
|---|---|---|
| 回答内容变化 | 同题新运行与基线的答案、要点命中、事实支撑、引用、自动疑点及有范围说明的语义核查 | 不能用仅改终态代替新内容改善 |
| 执行行为变化 | 不同 `run_id` 的工具动作、实际送模来源、证据覆盖、模型/工具次数、实际输入输出、预检、预留、未知量和耗时 | 不能把预算估算下降当作真实用量下降，不能把搜索摘要当正文 |
| 仅终态分类变化 | 对同一份已保存答案另存离线分析，保持答案、最终响应、事件、工具、来源和实际用量不变，显式列旧终态、新解释、规则版本及影响指标 | 不改旧快照，不伪装为新运行，不将分类贡献混入内容贡献 |

仅终态分析必须保留原答案和证据的摘要、原运行编号及指标分母；若同时有内容或行为变化，则另列新实测，不归入“仅分类变化”。预算上限、模型和授权范围维持方案约定。第 1A、1B 的实测与旧答案分类分析分开留档；未知实际用量始终明确显示。

输入指纹中的评分程序 SHA-256 及 Git HEAD 固定当前规则来源。后续协议同步可能修改 `run_metrics.py`、`run_eval.py` 等消费代码，须单列这些实现变更和终态口径版本；不得借协议同步修改要点匹配、数字/陷阱启发式等内容规则。如果以后单独授权规则修订，应保留原口径，另立版本，对所有保存答案统一离线复算。
