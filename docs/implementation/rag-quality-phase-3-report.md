## 1. 改动与边界

开始时 Git 工作区干净，见[输入及复现记录](evidence/rag-quality-phase-3-inputs.json)。保留原模型、主机、嵌入与重排模型、Docker 数据及知识库授权范围；单题仍最多 6 次模型、10 次工具、120 秒、64000 实际词元，输入预检仍为 16000 UTF-8 字节估算，输出最多 2048。为加载改动重启了本项目 ai-service；评测在健康接口就绪后执行。首次登录尝试发生在重启预热期，连接被关闭，未开始任何问题或模型请求，随后确认服务就绪再启动评测。

新增统一的 `WebDiagnostic`：保存端点、发生阶段、错误类别、异常类名、耗时、实际 HTTP 状态、经字符白名单检查的供应商 request_id，以及客户端、提取和超时层级。没有收到响应时状态为 null，不编造状态码。只读取明确的追踪字段，不保存授权头、密钥、异常消息原文或响应头集合。

Tavily 不再把所有 HTTP 异常统一称为连接失败：分别记录 connection、tls、proxy、read、write、remote_protocol、transport、timeout、http_status、invalid_response、response_too_large、extract_failed 和 empty_content。TLS 按底层 SSL 异常识别；客户端超时保留连接、写、连接池或读阶段。域名预检与响应中的网址校验有独立阶段。HTTP 200 的逐网址失败、空正文、缺少结果、重复或不对应的网址继续明确失败。

工具执行器保留异常诊断，并区分外层 tool/run 时限；成功请求也记录 HTTP 状态、耗时和追踪编号。诊断同步进入 `tool_finished.web_diagnostics`、`error_summaries` 及快照 `tool_results.web_diagnostics`，现有 v5 API/SSE 的事件 data 字段可直接承载，无需改变协议版本。所有本轮事件和快照的诊断及错误逐项一致。

没有增加自动重试、供应商切换、直接抓取、非法参数修复、输出修复或网址授权放宽。正式提取仍为 basic/text；后述探针未进入生产策略。也没有修改题干、关键词、参考答案、历史结果或评分规则。

## 2. 复现与超时核对

修改前直接调用运行容器中的供应商实现：搜索、W01 原网址、W03 原网址均成功，分别约 3.076、2.452、3.908 秒。因此本次没有重现历史连接故障，也不能把历史失败归因于当前代理、证书或超时设置。

可复现的是诊断信息丢失：通过 `docker exec -i ai-service uv run --no-sync python -` 输入临时诊断，在实际 `_post` 调用处注入 `httpx.ReadError`，得到 `TOOL_DEPENDENCY_FAILED`，诊断为 null，断言失败。修改后相同路径记录 extract/read/ReadError、耗时及 null HTTP 状态，断言通过。没有为此创建测试文件。

HTTPX 的阶段超时不能独自保证整个流式请求在给定墙钟时限内结束。本次补上整个请求的 `asyncio.timeout`，没有增加原有时限：默认供应商提取 15 秒 < 客户端阶段及总时限 20 秒 < 工具 30 秒 < 单题 120 秒。单题剩余时间可先于工具时限生效，记录 timeout_layer=run。提取参数取 `min(client_timeout - 1, 15)`，客户端配置范围由大于 0 改为 2—20 秒，保证提取参数至少 1 秒且小于客户端时限。当前运行配置未改变。

官方依据：[Tavily Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)明确提供逐网址失败数组、request_id 和提取时限约束；[HTTPX 异常说明](https://www.python-httpx.org/exceptions/)区分连接、读写、代理和各网络阶段超时。实现和诊断以本次实际异常及响应为准。
