# 统一取证结束流程：顺序 2 修复

日期：2026-11-02。本次对应“统一取证结束流程”，接续[调用预算修复](call-budget-step-1-report.md)，与之前 evidence_id 改造的“顺序 2”分开记录。

## 修复内容

[最终回答入口](../../ai-service/internal/biz/rag.py)统一关闭工具会话。原先模型正常调用 finish_research 时会关闭会话，但程序因调用上限、工具次数、重复查询或没有新证据而结束取证时，会话仍保留未结束状态。本次在进入最终回答时统一设置 finished，真实执行器随后拒绝任何新增工具动作。

正常流程保持“检索 → finish_research 选定已送模来源 → 登记最终证据 → LLM 生成答案”。达到程序限制时直接进入同一最终回答入口，不要求再消耗一次模型调用来发出 finish_research，也不伪造模型选定来源。最终回答仍只生成一次，不发送工具定义。

[那 5 项测试](../../ai-service/tests/test_rag_grounded_answer.py)改为当前取证流程和结构化回答：冲突资料分别保留、空结果可以结束、有资料仍可判断不足、合法引用确实来自实际最终请求、非法证据编号不发布。测试经过真实 ReadOnlyToolExecutor、MaterialProcessor、分块器、ToolModel、RAGBiz；仅检索依赖、仓储与模型返回使用固定数据，未把 finish_research 和来源验证替换为虚假的成功结果。

冲突版本测试使用两份分别存储的版本文档，核对独立身份、不同版本及各自原文；不把同一文档的过期切片当成当前版本。重复查询测试也使用真实执行器，核对重复动作未执行、只生成一次最终答案，取证停止原因保留为 repeated_call。
