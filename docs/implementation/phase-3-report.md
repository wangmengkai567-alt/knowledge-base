# 第三阶段完成记录：有边界的后端问答循环

日期：2026-10-28（Asia/Shanghai）。

第三阶段代码与直接功能检查已完成。同步问答和现有 SSE 问答均已接入同一个 Python 执行循环。前端联网开关、实时过程事件展示、运行资料落盘及七天清理仍在第四阶段实施。本阶段没有新增或修改测试、评测文件，没有执行完整题集，没有提交或推送。

## 交付行为

1. `AnswerRun` 持有用户和来源范围、运行编号、执行状态、实际送模来源、工具结果、用量及顺序事件。状态区分完成、资料不足、预算耗尽、重复查询、工具失败、模型失败、无效答案、超时与取消；失败不会写成正常答案正文。
2. `RAGBiz` 取代固定的一次检索与生成。模型可以拆分子查询、观察结果后补查，也可以直接依据已有资料回答。知识库空结果继续交给模型判断；允许联网时提供网页工具，未开启时不提供。工具失败或部分失败立即结束，不以故障为理由改走另一来源。
3. 单步模型协议从 service 层移至 `biz/tool_model.py`，删除旧 `service/tools.py`。工具参数、权限和执行仍由 `ReadOnlyToolExecutor` 集中检查，模型不能覆盖用户、知识库或联网范围。
4. 工具调用按实际查询规范化后去重。查询大小写、空白、关键词/网址排列以及返回数量变化不能用来重复执行相同查询。被拒绝的动作有独立事件，最终作答轮禁用工具。
5. 来源按实际送模内容分配稳定的正整数引用编号。工具获取但未送模的结果保留在内部工具结果中，不进入已使用来源列表。完整历史、工具定义、系统提示和资料共同参与输入预算；裁剪正文时同步裁剪分块位置。不同内容或不同时间的来源快照保留各自记录，不用评分覆盖冲突资料。
6. 更新回答提示，删除资料非空就必须作答的要求；没有拒答后追加强迫回答的再次生成路径。最终响应明确声明 `answered` 或 `insufficient`，后端解析为运行状态，不按中文答案字符串猜测成功与否。
7. 发布前检查最终响应结构、引用格式、引用编号归属，以及正常回答是否缺少引用。无效答案不发布，也不额外调用模型修补。事实结论逐处引用、摘要与正文区别、冲突与时间信息由提示明确要求；格式通过不代表语义支撑成立，结论支撑仍由第六阶段评估。
8. 内部事件记录模型调用及用量、工具动作及参数摘要、结果数量及错误摘要、资料准备、答案检查和结束原因；不记录工具轮模型解释或内部思维链。完整资料只保存在本次运行内存中，未声称具备持久保存或恢复执行能力。

## 执行预算

| 边界 | 实施方式 |
|---|---|
| 模型最多 6 次 | 调用前计数，包含最终回答；第 6 次只能回答 |
| 工具最多 10 次 | 执行前计数，失败调用也计入；同轮多个请求逐个检查 |
| 整次最多 120 秒 | 授权、模型和工具共用截止时间，每次动作前再次检查 |
| 单次工具最多 30 秒（默认） | 沿用第二阶段配置和取消机制，配置最大 60 秒 |
| 单次模型输入最多 16000 | 包含完整提示、问题、工具说明、历史及实际资料 |
| 单次输出最多 2048 | 下发供应商限制，取得实际用量后再次检查 |
| 累计输入输出最多 64000 | 每次调用前预留本次额度；取得用量后按 `max(估算输入, 实际输入) + 实际输出` 扣减 |
| 最终回答预留 | 探索前为最终一次完整输入及回答留出额度，并预留调用次数；无法容纳新动作时用上一次完整上下文结束 |

`RunLimits` 只能在上述程序上限内收紧限制。请求不能覆盖执行上限。`top_k` 作为本次知识库工具的返回数量上限，接口接受 1–10，与只读工具边界一致。

输入方式仍明确为 `utf8_bytes_estimate`，不是千问精确 token 计量。实际输入和输出、估算输入、保守扣减量分别保存。请求失败或取消而没有供应商用量时，保留预扣额度并增加 `unreported_model_calls`，不把未知用量记成已经测得的零消耗。供应商若返回超过预检上限的实际用量，会立即终止，不再发起后续动作。

达到预算或重复查询后，可以在预留额度内取得经过引用检查的最终说明，但终态仍保留预算耗尽或重复查询原因。当前 SSE 仅将正常完成和资料不足的答案作为回答发布，其他终态发送明确错误。第四阶段再完善受限结束时的页面呈现。

## 接口与运行入口

- 原同步和 SSE 路由沿用，均执行一次 `RAGBiz.query()`；删除固定检索生成的另一套业务判断。
- 请求新增 `allow_web`（默认关闭）和 `user_urls`（最多三个用户明确提供的网址）。认证用户由 HTTP 层传入，执行器仍独立校验知识库归属。
- 同步结果新增 `run_id`、`status`、`stop_reason`、`error_code`、`usage`、`events`。网页来源 DTO 保留 URL、标题、获取时间和实际内容，知识库来源继续保留分块范围。
- 现有 SSE 在来源和检查后的完整答案之外增加统一终态结果；失败携带状态、原因及用量。内部动作事件尚未实时对外推送，不声称已完成第四阶段。
- 内部 `RAGBiz.query(..., cancelled=asyncio.Event())` 支持取消；外部任务取消继续向上传播，正在等待的模型或工具被取消并清理。未声称供应商同时停止计算或计费；完整前端取消交互仍在第四阶段。

未创建检查脚本文件或修改测试文件；以下均为本次直接运行的功能检查。

| 检查 | 结果 |
|---|---|
| 固定资料下的执行分支 | 知识库回答、网页搜索后读正文、知识库空结果后网页补查、仍无资料均取得预期终态 |

这里的 **sandbox（沙箱）仅是既有知识库笔记的主题及问答样题**，用于核验检索、模型回答和引用映射。本阶段没有实现独立沙箱，没有开放任意代码或 Shell 执行工具；样题回答中描述的沙箱能力不等于本项目具有这些能力。

网页两步取证的循环行为已经使用固定资料检查；上表明确区分真实供应商调用。Tavily 连接问题没有通过换供应商、跳过 TLS 校验或伪造成功结果处理，网络恢复后的实际网页端到端成功记录仍需补验。
