# 第一阶段完成记录：真实评分与统一资料处理

日期：2026-10-28（Asia/Shanghai）。

第一阶段业务重构已完成，第二阶段尚未开始。沿用千问及存量向量，不新增数据库字段，不重新上传或全量嵌入资料。

## 已交付的行为

1. 浏览器只提交问题和所选知识库范围。后端检查归属后协调跨库检索，真实检索结果直接进入资料处理与生成；文档列表复用同一次问答返回的 `retrieval_results`。
2. 删除 `load_by_ids`、`refine_for_generation`、请求中的 `chunk_ids`、生成模块读取私有阈值及再次硬过滤的路径。旧请求字段会被拒绝，不保留兼容生成分支。
3. 统一资料模块为 `ai-service/internal/biz/materials.py`。相关性规则只有一个入口，重排阈值仅应用于真实重排分；向量分、BM25 分和 RRF 分不会套用重排阈值。
4. 保留各路评分的类型、数值及计算方式，包括余弦相似度、BM25、混合检索 RRF、查询变体 RRF 和重排模型分。没有真实评分时保持空值。邻块不会获得人为补造的相关性分数。
5. 相邻分块合并后，`sources` 保留连续的引用编号、文档信息、所有实际参与的分块及原文字符范围。`content` 与 `segments` 精确对应实际送模正文；截断后裁剪映射。检索评分元数据不夹带未送模的原文。
6. 来源卡片按引用编号展示，可查看本次实际送模片段并打开原文。列表筛选不改变生成所用资料；收藏页去掉把不同排序分当成百分比的展示。
7. 同步与 SSE 共用资料处理和来源序列化。拒绝空回答、缺失引用及越界引用；依赖异常明确返回错误，不伪装成正常回答。
8. 删除重排失败时返回原候选、智谱分数异常时替换为词面重排、查询变体与关键词分支失败时静默降级的逻辑。无效、缺分或不完整的重排响应明确报错。
9. 删除旧浏览器答案与检索缓存及其读取逻辑，旧缓存不会进入新问答。删除旧邻块处理模块、按字符数截断上下文的辅助函数和无效的 `rerank_top_k` 配置。

为了使一次问答只调用一次生成，并保证送模资料与引用一致，原定第三阶段清理的“模型拒答后追加必须回答提示再生成”逻辑已随旧生成路径一并删除。第三阶段仍需实现工具循环、完整执行预算与终态。

## 输入预算及准确性边界

当前唯一确认容量的对话模型为 `qwen3.8-flash`。单次输入预算为 16000，回答上限为 2048，结合准备阶段确认的模型上下文容量预留回答空间。更换未确认容量的模型会明确拒绝启动资料处理，不能沿用当前模型规格。

尚未取得可核实的该模型精确分词器，因此 `input_measurement` 明确为 `utf8_bytes_estimate`。完整系统提示、问题、消息包装与资料一起进行保守 UTF-8 字节估算；预算接口还包含工具说明和执行记录的计量位置，本阶段二者为空。估算值与供应商返回的实际输入、输出用量分开记录。实际用量超过上限时明确报错。

该估算用于本地裁剪，不代表精确 token 计量，也不构成对供应商计费单位的数学上界证明。已知计量不确定性没有被描述为已解决。工具调用累计预算及超时在后续阶段实施。
