# 调用预算与最终回答：顺序 1 修复

日期：2026-11-02。本次对应“修正调用预算和最终回答流程”，与之前原文分块修复的“顺序 1”分开记录。

已修复：`RunLimits` 只接受 2—6 的整数模型调用总次数；总次数为 1 时，在创建配置时立即抛出明确错误，不再进入运行后因没有取证而停止。默认总上限仍为 6，工具、时间和词元上限不变。

总次数包含取证决策和最终回答。已有执行器会为最终回答预留一次调用；达到模型或工具上限后，使用已取得的资料进入最终生成。有充分证据时可以完成回答；没有充分证据时生成缺失说明，并保留取证预算达到上限的停止原因。最终生成使用独立的 `generate_answer` 接口，不发送工具；即使供应商返回工具动作，也不会执行。

本次生产修改位于[运行配置](../../ai-service/internal/biz/answer_run.py)。现有收尾逻辑通过真实 RAGBiz/ToolModel 循环验证，无需增加另一条回答路径。对应[预算测试](../../ai-service/tests/test_rag_grounded_answer.py)改为先模拟一次检索，再检查预留的最终生成调用；模拟模型与执行器仅在这些预算测试内补齐所需接口，没有改动其他旧流程测试。

4. 最终模型返回工具动作时明确拒绝；不会执行第二次工具调用。
5. 工具次数达到 1 次上限后，仍使用预留调用生成有依据的答案。
