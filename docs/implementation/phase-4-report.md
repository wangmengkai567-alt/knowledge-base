## 已交付行为

1. 同步问答与 SSE 共用一次后端执行和同一结果转换。删除等待整次问答完成后才模拟发送 `sources/chunk` 的旧业务路径。SSE 使用协议版本 4：连续的 `event`、完整的 `result` 和 `[DONE]`，不发布逐字草稿。
2. 过程事件包含运行编号、顺序号、经过时间与动作摘要。开始、模型调用、工具开始及完成、来源更新、回答引用检查和运行结束均能追踪；不输出模型内部思维链。来源更新只登记已进入模型请求的资料，工具取得但未送模的资料不作为回答依据。
3. 前端一次请求取得过程、来源、文档列表、最终答案、用量和结束原因。页面展示查知识库、搜索网页、读取网页等阶段；按后端状态区分完成、资料不足、预算耗尽、重复查询、工具失败、模型失败、无效答案、超时和取消，网络断流单独报错。预算或重复查询终止时，经过引用检查的说明可以显示，但同时保留受限结束提示。
4. 首页可以在提交前明确开启联网，结果页也提供联网开关。首页选择通过本次导航状态传递，不从问题内容推断联网许可；默认关闭。切换知识库或联网许可会建立新的运行并取消旧请求。
5. 答案中的有效引用链接直接打开本次实际使用的资料快照。知识库来源展示合并后的各分块、字符范围、文档时间和截断标记，可继续跳到原文分块；目标分块已变化时明确提示。网页来源区分搜索摘要与正文，展示获取时间、实际内容和原网址。代码中的引用文字与未知编号不自动生成引用链接。
6. 来源绑定到 `run_id + citation_id`。删除按问题文字阻止再次执行的旧逻辑，只在请求仍执行时合并相同的重复触发；完成后再次提问会建立新运行。当前没有答案缓存，不引入新缓存；前端拒绝旧协议、顺序缺口、跨运行混用和缺少终态的响应。
7. 停止、换题和离开页面均中止请求。HTTP 显式关闭内部事件生成器，取消执行任务并等待模型、工具清理和快照保存，取消后不启动下一动作。关闭连接后无法再向该连接推送取消终态，服务端终态以本地运行记录为准；不声称供应商必然同时停止计算或计费。

## 运行记录

保存位置固定为本项目 `ai-service/data/answer-runs/user-{用户编号}/run-{运行编号}.json`。当前 Docker 源码挂载下，对应容器 `/app/data/answer-runs/`；文件留在本机，目录已加入 Git 忽略。

每份快照包含协议版本、问题、允许范围、执行限制、开始及保存时间、到期时间、事件、终态、用量、检查后的答案、实际送模来源，以及工具实际取得的资料和错误。工具取得但没有送模的内容仅在 `tool_results` 中保存，不能冒充最终答案来源。记录足以在第六阶段离线核对引用和资料，不需要重新检索来还原证据。

记录在执行结束或取消后原子保存，成功保存后才发送最终 `result`。保存失败会明确报告传输或保存失败，不发布看似正常的最终回答。并发保存与清理在同一进程内串行保护。

保留期限为七天：每次保存前、服务启动时及运行期间每小时清理到期文件，包括遗留的临时写入文件。服务停止时不运行清理，下次启动会先清理；运行期间物理删除最迟在下一次清理发生。清理失败有明确日志。记录不会用于自动重连、恢复执行或进程重启后续跑。
