# 问答质量优化的一手实现核查

核查日期：2026-10-29（中国标准时间）。本轮通过 GitHub 连接器重新读取固定提交的源码，并查看千问官方接口文档；未运行第三方项目，未调用本项目的模型或评测接口。以下“本地建议”是结合已记录失败现象作出的设计判断，不是第三方项目效果保证，也不是优化后的实测结果。

## 建议采用的方法

| 本地问题 | 已核实的参考行为 | 本地建议与代价 |
|---|---|---|
| 到达最后一轮后，即使有合法回答仍记为预算失败 | Onyx 在最后一轮禁用工具；没有工具调用时结束循环，有最终回答则正常发出停止事件。源码没有因“这是最后一轮”就统一抛出预算错误。 | 分别记录“为什么停止探索”和“最终回答是否有效”。允许最后一轮按实际资料回答或说明资料不足，保留轮次限制事实。不能把取消、超时、真正超出硬预算或无效引用改成成功。此项会影响终态口径，前后比较必须明确列出，不能只展示更高成功率。 |
| 工具定义、历史记录和正文挤占输入 | Onyx 在组织历史前扣除工具定义的实际计量开销；最后一轮工具清单为空。搜索工具在选择资料前先做总量裁剪，再选择值得阅读的片段。 | 收尾阶段删除不再使用的工具定义；按整次请求计算资料可用空间，正文集中保留一次。选择时兼顾相关性和问题各部分覆盖，不因资料在列表后面就先截去。不能把估算单位说成精确词元，也不应直接放大既定上限。 |
| 模型反复改写查询，没有新增证据仍继续 | Khoj 把既往工具与参数组合登记起来，重复组合生成警告且不执行；文档与网页查询把以前的查询传给下游。 | 保留本项目已有动作去重，再用“是否新增可用资料”约束继续搜索；连续无进展时收尾说明缺失，而不是继续穷举同义词。这里的“连续无进展停止”是本地设计建议，未声称 Khoj 已实现同样策略。需防止将多来源问题中的必要新子问题误判为重复。 |
| 检索命中不等于能支撑答案 | LangGraph 示例分别判断“片段是否相关”“回答是否受资料支持”“回答是否解决问题”。 | 把检索命中、证据覆盖、答案完整性、事实支撑作为不同检查项。先修复送模资料覆盖和回答约束，再考虑额外模型评审。不能把关键词命中或引用编号存在当作事实支撑。每次增加在线评审都会消耗既定调用次数与输入预算。 |
| 有来源但引用链可能脱节 | RAGFlow 为智能体内部执行的工具包装来源记录，统一写入运行状态，供后续引用使用。 | 来源应从实际工具执行入口登记，正文选择、引用编号和评测快照保持同一份映射。本项目已有此设计，可保留；不能在离线评分时重新检索并替换当时证据。 |
| 仅凭提示要求结构化输出，仍出现排版文本或缺括号 | 千问官方支持在请求中声明结构化输出；只在提示词要求 JSON 和调用接口的结构化约束是两件事。 | 在已验证支持的请求阶段显式启用结构化输出，继续校验业务字段和引用。禁止通过剥代码围栏、补括号、转换非法参数或失败重试掩盖协议错误。详见后文的适用边界。 |

适用判断：最后一轮不再携带工具定义、预算按完整请求计算，可直接借鉴控制原则；多次额外调用模型进行资料选择和扩展会增加成本，不宜整套照搬。它还包含从普通文本抽取工具调用的兼容处理，本项目明确禁止，不能一并移植。

## 千问结构化输出的接口核查

官方文档确认 Qwen3.8-Flash 支持 JSON Object；请求设置 `response_format={"type":"json_object"}`，提示中须包含 JSON。该模式保证语法，不保证业务字段；当前支持表也列出 JSON Schema。[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)

[工具调用文档](https://help.aliyun.com/zh/model-studio/qwen-function-calling) 单独列出该模型的原生工具支持。[兼容 Chat 接口参考](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions) 分别定义输出格式、工具、自动选择与禁止工具参数；工具存在时响应数量须为 1。该参考还说明千问的强制工具选项不能保证或不支持，不应靠它强迫初始检索。

**这几页没有给出该模型同时启用工具与 JSON 模式的完整联合示例；不能从分别支持推出当前网关的组合已验证。** 可先在明确收尾阶段去掉工具定义，再使用结构化输出；探索阶段若要同时启用，须做真实接口验证。本文未做此验证。实际传参采用关闭思考模式时，不需要为了结构化输出改成思考模式。

官方另提醒输出上限可截断 JSON。本项目已批准硬输出预算，不能照抄“取消上限”，应保留上限并把被截断的输出明确记为失败。也不能照搬文档中的失败重试或格式修复建议。

## 前后对比必须保留的边界

1. 优化前冻结原始答案、快照、配置、完整题集、评分表达表和统计口径；新结果另存，不覆盖旧记录。
2. 预算数值和计量单位分别记录。删除无用工具定义或重复正文属于减少浪费，不等于提高额度；不能把字符或字节估算直接称为真实词元。
3. 正常完成、资料不足、格式错误、引用错误、预算停止、超时等分别报告。若调整“最后一轮的合法回答”如何归类，必须单列该变化及对应题目，避免用终态重命名冒充答案质量提升。
4. 关键词、回答完整性、事实支撑、引用映射分别比较。启发式幻觉标记中的合理推导与元数据误报应留人工核对记录，不临时放宽自动规则。
5. 相同模型、题目和知识库范围下执行全量复评，并列展示逐题变化、调用量和耗时；诊断小样本只能帮助定位问题，不能替代最终全量结果。

优先顺序建议：**收尾时移除工具定义并明确结构化输出 → 减少重复上下文、保障关键证据覆盖 → 无进展时停止检索 → 加强答案依据与缺失说明 → 相同标准全量复评。** 单纯扩大次数上限、放宽引用、修改评分规则不构成本轮质量优化方法。

## 后续本地实测补充

主执行任务随后使用当前服务完成了能力探针与完整 100 题评测。两种结构化模式均曾与自动工具调用组合成功，但完整题集仍出现 9 次无效回答；简单探针不能证明稳定支持。实际接入地址与上述百炼官方文档列举的域名不同，已在 [优化报告](../implementation/rag-quality-optimization-report.md) 中单列该适用边界。原始响应、用量和失败均保留，没有切换模型或服务地址。
